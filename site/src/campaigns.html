How this was measured

Each run covers the same 81 input cases. The second run reverses their order. Mech is faster in 61 cases and slower in 20 in each run; the exact cases can differ between runs. A ratio strictly below 1 is a win, above 1 is a loss, and exactly 1 is a tie.

Seconds are the medians of each executable’s timings. Comparisons use the geometric mean of 96 paired-block time ratios, so the comparison is not calculated by dividing the displayed medians. Output sizes include the retained prefix. Both implementations use level 12; their compressed streams can differ.

What counts as a comparison?

A comparison requires the same task, environment and agreed measurement scope. A timing without a matched reference remains available under “All measurements” and has no speed ratio. A fixed Mech baseline records later changes against a previously confirmed build.

Runtime tasks, compiler builds and native compression calls measure different operations. The task details state what each timer includes. Sources, versions, individual observations and earlier runs remain available with each result.
