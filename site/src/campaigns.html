How controls and history work

Rust is the default control. A confirmed Mech win can establish a pinned Mech control for that task and measurement; it stays fixed for future comparisons. A single fast sample never changes the control. Each control links to its actual samples and source.

The latest view shows one accepted Mech result per task, preferring its declared execution path. Each row identifies its measurement and run; different boundaries are never combined into one score. Choose a run or execution path to inspect earlier observations and failed qualifications.

Compiler history requires the same task, source, schedule, boundary, backend and environment. Rust task comparisons retain each implementation's source, compiler and timer details. Resident controls use independent typed Rust implementations with native ownership; Mech also performs runtime scheduling, admission and budget accounting. Compression reports output size alongside time because Mech level 12 and Rust zlib-rs level 9 use different codecs. Related Post Gen preserves the original Rust example's preinitialized pool advantage. Resident turns remain diagnostic measurements; managed storage and process RSS have separate meanings.

Independent forks and all adverse observations remain available. Suspected regressions need independent confirmation. Shared-runner timings never fail CI.
