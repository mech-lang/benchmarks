# APL tree publication

This additive path admits binary trees after one complete six-process cohort:
three GNU APL observations and three matched Mech controls at N=21. The compact
and optimized labels share the same authored source, setup and three timings.
The alias adds no native process and makes no optimization claim.

The complete source bundle is the unchanged 40-unit tree application plus the
one-unit workspace assignment. Both canonical and physical totals are 41;
formatted counts are unavailable. Workspace scale 200 is set inside each timed
process. Startup, parsing, computation, complete output and shutdown remain in
the wall-clock measurement.

The exporter checks the new independently reconciled source/runtime bindings
against the exact previously reviewed interpreter image, launcher and recorded
static dependencies. It preserves the older runtime receipt's original scope
and does not claim a new per-process loaded-image inventory. Earlier failed
tree and diagnostic attempts remain linked with their original dispositions.

The catalog transformation requires nine existing APL workloads and adds only
binary trees. Existing programs, samples, source files and failure evidence stay
unchanged. A new LOC or runtime minimum rejects the import. The APL aggregate
expands to ten workloads through a recorded history boundary with no rebasing.

## Compatibility with the current publication checkout

The importer does not load, pin or rewrite `site/src/traits.mjs` or the language
module. It changes only the two catalog documents and normalization history.
Existing language classifications, source records, measurements and non-APL
aggregates are preserved. This avoids requiring the original checkout's older
traits bytes in the publication checkout.

Direct-link verification walks only the new APL candidate and its consumer
sources; it does not traverse existing Prolog catalog references or expand the
Prolog declared gzip evidence. Existing successful history entries and their
snapshot bytes continue to use the unchanged parent validator. The APL six-slot
reports, counted sources and new review receipts use their exact raw identities;
there is no generic compression exemption or receipt-hash substitution.

After the tested history leaf is copied to the publication checkout, its
`tools/verify_repository.py` must select `normalization_history_apl_trees.py`
before the new admission is verified. Keep the original evidence checkout's
verification entry point and the frozen producer/plan chain unchanged.
