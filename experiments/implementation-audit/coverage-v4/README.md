# Audit coverage with published-source protection

This additive reconciliation retains v3's exact source inspections, then applies
fresh captured-source identity evidence to 34 profiles whose broad adaptation
metadata had incorrectly left their published source editable. No program,
source count, timing, attribution or prior frozen coverage report is rewritten.
The current ownership classifier now enforces that same protection for future
inventories. Existing origin classifications remain separate from edit rights.

The inventory still has 1,070 profiles. There are now 385 protected profiles,
639 editable profiles and 46 unresolved ownership profiles. Among the editable
profiles, 334 have a static source inspection and 305 do not. There are 570
unique editable source bundles. These are inspection/ownership counts, not native
qualification, optimized-source completion or globally fastest claims.

All 34 newly protected profiles leave the unreviewed editable queue. That scope
correction explains the changed totals without claiming new source inspections
or treating published programs as new optimization work. All earlier coverage snapshots
remain immutable. The source identity evidence and acquisition limitation are
in [the protection packet](../upstream-protection-v1/README.md).

`build.py --check` rehashes retained source boundaries, verifies exact evidence
inputs and recomputes the complete family/profile summaries. Missing legacy
Clojure/Gleam paths use the unchanged exact catalog UTF-8 source, as in prior
reconciliations. No native process is started and no admission is granted.
