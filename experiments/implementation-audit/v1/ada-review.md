# Ada: derived-source review with upstream protection

The retained catalog contains **17 Ada profiles: eight locally adapted profiles
and nine unchanged upstream submissions**. This pass read the complete adapted
source bundles, including combined package specifications/bodies and application
FFI. Exact hashes and unchanged-source protection are recorded in
[inventory.json](inventory.json); complete text remains in
[programs/ada](../../../programs/ada/). No Ada/native process, compilation,
benchmark, browser or generator was run or changed.

The nine unchanged Game submissions remain byte-preserved. Their presence in the
table identifies coverage and runtime-comparison opportunities, not authorization
to rewrite them. Candidate source alternatives apply to separate suite-owned
forks/adaptations. Contributor comments, original citations and licenses remain
attached. A saved `strict:true` or “optimized” description does not resolve the
specific scheduling/lifetime questions below by itself.

## Priority and source accounting

First resolve the two source-level qualification issues: Mandelbrot's worker
population and binary-tree lifetime/worker edge cases. Then compare nucleotide
parser/API choices and safe buffering. The retained Ada sources already offer
ordinary tasking, growable hashed maps, fixed-width integers, heap-string views,
PCRE2 JIT, APR pools and mutable GMP cells. Their source/performance tradeoffs are
real; a broad “Ada was not optimized” conclusion is not supported by this review.

The smallest-idiomatic suggestions are complete alternative source designs, not
new counts. Ada package specifications/bodies, forward declarations, `begin/end`,
record aggregates, meaningful pragmas, task entries and FFI must follow an
explicit retained owner rule. Merely placing multiple declarations on one row,
joining literal data or omitting library declarations from the bundle is not an
expressiveness improvement. Pure expression functions and ordinary container
operations are legitimate; do not expand their implied work into scalar LOC.

Qualified formatted counts remain separate from retained normalized LOC; byte,
gzip and BPE metrics use actual application/submitted partitions and include
their retained comments/whitespace. APR, GMP and PCRE implementations are general
libraries, while source-owned benchmark loops, domain parsing, formatting and
application FFI are visible and counted under the existing boundary. Preserve
all contributor notices and original file citations on every adapted fork.
