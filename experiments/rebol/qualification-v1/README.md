# Rebol bounded qualification consumer

The additive [consumer](../../../tools/qualification/rebol_qualification.py)
joins actual extension4, primitive19, shared149 and work3 evidence with fifteen
exact authored source projections before a full timing plan can use them. It
starts no native process and changes no producer, source, count proposal or
historical receipt. Its 17 focused test methods passed on 2026-10-15 UTC in
[the repaired-run record](../../shared/pure-validation-20261015/post-prolog-pure-validation-repaired-v1/report.json); the earlier failed run
remains in [the initial record](../../shared/pure-validation-20261015/post-prolog-pure-validation-run-v1/report.json). No successful
manifest or actual qualification is supplied with this source draft.

The existing extension and primitive replay is reused through
`rebol_bounded.primitive_inputs`. The only new replay logic covers the completed
shared149 and work3 stages, their durable controller identities, the exact count
joins and independent source/work dispositions. The original common mutex and
all inherited leases stay continuously held. The two additional closed-stage
leases are held separately, without modifying an outer helper's lease list.

The original failed SDK generation remains failed. Its independently approved
29 generated outputs are used only through the existing output-reuse chain.
The selected corrected C source must match the actually built and approved
extension. Neither a source proposal nor a successful producer flag is an
independent admission.

The actual extension and primitive approvals retain their existing schemas and

The new stage replay requires exactly 149 or three ordered captures. It

## Exact source and work review

A count proposal alone is insufficient. The separate count disposition uses
schema `rebol15-independent-source-count-review-v1`, status
`qualified-exact-fifteen-source-owner-counts`, independent review and
`canonical_LOC_admitted: true`. It binds the proposal and approved rule through
`references`, the exact rule version, all fifteen `sources`, and ten `bundles`.
Each source summary contains its absolute path, SHA, canonical LOC and physical
LOC. Each bundle summary contains its ordered member identities and both sums.
Full timing and chart admission remain false.

Every source digest must first be frozen through independent owner review.
The unchanged `count_source` rejects unset digests. Its complete replayed owner
projection must equal the original unqualified proposal, with only the
source-identity review flag compared in its original false state. Exact owner
spans, decisions, source memberships, all per-file counts and bundle totals are
checked. `formatted_loc` remains null.

There are ten authored mains and five support files: IO, loader, complete
corrected C, bigint facade and regex facade. Eight bundles have four files;
pidigits and regexredux each have five. The old and corrected C are never both
counted, nor are the old and corrected Fann mains. Every selected main must
match the actual shared149 source, and every support file must match the actual
extension/facade inputs. Runtime, SDK, compiler and vendor libraries remain
disclosed provenance rather than extra authored application LOC.

The work disposition uses schema `rebol-independent-bounded-work-review-v1`,
status `qualified-exact-bounded-outputs-and-source-work`, independent review,
and true `bounded_output_qualified` and `required_work_qualified`. It binds the
exact three references for both completed stages, runtime/image, fifteen source
identities, complete replayed `bounded_validations` and `work_observations`, and
ten `source_work` entries. Each entry binds the selected main, actual supporting
review references and the scope `exact-source-and-bounded-evidence`.

The actual source/work review must preserve these limits:

- Tree: the N4 graph and automatic collection survival include a disclosed
  extra root alias. They do not establish per-tree reclamation or full-size
  survival.
- Pi: the actual full-operand forwarding trace belongs to the instrumented
  bounded wrapper. It is not a trace of an uninstrumented full-size process;
  separate signed-floor tests do not establish negative N27 operands.
- Maps: the actual seven complete maps and final backing-series storage are
  observed. Displayed addresses are low32 tokens. Hash-bucket capacity and a
  growth trajectory are not observed. `map_growth_source_review` separately
  binds the retained insertion/growth implementation and application work;
  a final snapshot cannot be relabeled as observed growth.

The final manifest's exact `scope` has true `required_work_qualified`,
`canonical_source_count_qualified`, `bounded_output_qualified`,
`extension_abi_qualified` and `full_primitive_fixtures_qualified` only after those
independent actual approvals exist. `runtime_source_equivalence_proven`,
`full_timing_qualified` and `chart_admission` stay false. Version/source
association and observed extension layout/load do not prove a bit-for-bit
runtime rebuild; this consumer neither invents that claim nor adds a new
rebuild prerequisite. Declared image closure and the actual layout/load
observations remain separately identified.

## Timing consumer interface

`review_context(manifest_path, manifest_sha, on_exit_failure=None,
final_consumer_check=None)` yields `(admission, held)`. Admission is deterministic
JSON with schema `rebol-pre-timing-admission-v1`, the manifest reference, ten
ordered `bases`, runtime/image disclosures, references, unavailable inputs,
artifact closures, durable jobs, lease identities and the scoped disposition.

Each base preserves its original profile ID, benchmark, main path/SHA,
`language: rebol3`, direct command prefix, original evidence cwd,
`maximum_workers: 1`, and `input_kind: stdin` or `integer-argument`. Ordered
`physical_inputs` disclose counted file roles and individual counts; bundle
canonical/physical sums and null formatted LOC are explicit. Roles are
`application`, `application-helper`, `application-launcher`, and
`general-library-helper` for the whole corrected C.

The environment policy contains the fixed C-locale/thread values,
`fresh_directories` mapping HOME and REBOL_HOME to `home` and TMPDIR to `tmp`,
the exact extension variable, false ambient-loader overrides and no diagnostic
flags. The later producer expands these under its own fresh output directory.
It must not reuse a bounded diagnostic's HOME or add an interposer.

The disclosed alias policy permits compact/optimized forms of one authored
baseline without a distinct optimization claim or copied timing. Creating
separate execution IDs and fresh samples belongs to the later full producer;
there remain ten unique base bundles and fifteen unique counted files.

`held` provides the open common stream, immutable tuple of leases, shared
`pins` and `resolutions`, the unchanged evidence helper, the exact Rebol output
checker and `recheck()`. New timing inputs may be added to the shared maps.
An immutable snapshot prevents removal or rebinding of qualification-owned
entries; admission content and original closure inventories are also protected.
Recheck validates all accumulated inputs, original absence candidates, complete
artifact and durable inventories, then named leases last.

On context exit, prerequisite replay occurs even after a consumer-body error.
The final consumer callback runs only after that replay succeeds. Body, replay
or final-callback errors invoke cleanup before lease release and remain errors.
Late failures from an inherited context's own final check also invoke the
failure callback if it has not already run. That callback must inspect the
retained common stream and must mark ownership false if the inherited context
has already closed it; a previously written owned success terminal must be
downgraded. Callbacks take no arguments.
