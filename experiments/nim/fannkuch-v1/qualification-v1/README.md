# Nim fannkuch bounded qualification protocol

Source prepared only. The controller and its nine offline regression methods
have not been executed. No Nim/compiler/native process was launched by this
packet. The candidate sources, original source-proposal plan, proposed counts
and all retained results remain unchanged.

`protocol.json` binds this exact controller and source packet. A future
`--prepare` operation validates and binds the restored 6,770-file Nim 2.2.12
tree, original compiler/build receipts, retained external Clang/SDK/library
pins and all eight valid-domain corpus outputs. It starts no native process,
but file-tree hashing still requires the common mutex and a cleared work
window. The subsequent native run requires the exact resulting plan digest.
Every command and failure receives exclusive durable raw streams and a process
receipt; a failed attempt is never overwritten or silently retried.

The controller has no pilot, full-input, quantitative timing, chart admission,
source-count approval, or catalog-write mode. It records process durations only
as diagnostic receipts. Any later quantitative study needs its own reviewed
plan and explicit quiet-window clearance.

## Exact build scope

Both retained controls and all four proposed candidates are compiled normally
with the untouched restored distribution. Compact and parallel historical
recipes must have identical flags after normalizing only compiler, standard
library, cache, output and source locations. Nim 2.2.12, the C backend, Clang
22.1.8, `-d:release`, ORC, threads, serial compilation, SDK 14.4 and disabled FP
contraction remain bound. No CPU-target, unchecked, fast-math, or alternate
library configuration is introduced. The original unused package search paths
remain verbatim; all application imports are pinned standard modules.

The completed attempt will preserve the actual compiler version outputs,
normal/witness commands and diagnostics, full generated C and native build
metadata, executable hashes, linked-image listings and normal executable
disassembly. It checks actual C flags and configuration files. An independent
review must still inspect the emitted reversal, array value-copy/no-alias
behavior and byte element layout; artifact presence alone does not certify
these properties. Source counts remain null/unapproved until the separate
native owner and independent source reviews finish.

## Deliberately bounded work evidence

This new qualification protocol supersedes only the original source proposal's
tentative detailed trace range `n = 1..7`: detailed traces are now limited to
`n = 1..6` to bound evidence size. The frozen proposal is preserved. Successful
whole-output checks still cover all eight shared valid-domain cases `n = 1..8`
for every normal source. The pinned independent Python reference is recomputed
and must agree with the saved corpus bytes. Larger bounded cases use complete
output checks without verbose traces.

The retained sources explicitly accept only `1 <= n <= 12`. The shared corpus's
`n = 0` successful empty-summary extension is therefore outside their contract.
This packet honestly records `0`, `-1`, `13`, missing and noninteger arguments
as expected source rejections; it does not claim nine successful shared cases,
alter a source assertion, or silently broaden the accepted domain.

Each separate untimed witness application is an exact, retained source delta.
It adds events before/after the existing operations and an optional diagnostic
entry for invoking the unchanged parallel worker on an arbitrary rank range.
The normal binary's source is never replaced by the witness. Every witness
run at `n = 1..6` must produce the exact same complete output as its normal
binary and the shared reference.

To observe actual standard-library swaps, the witness uses a private copy of
the entire library directory. Exactly `lib/pure/algorithm.nim` changes: trace
helpers are added and a trace write follows the existing `swap(a[x], a[y])`
inside `reverse`. All original index arithmetic, swap statements, endpoint
updates and loop tests remain unchanged. Every other copied library file must
match its original pin. The normal build continues to use the untouched
distribution; both original and instrumented helper sources and their exact
diff are retained. This observer is never used for timing.

The replay validates every global rank, complete permutation, rotation-counter
state, scratch copy, prefix reversal, endpoint swap and post-swap array,
permutation flip count, checksum sign, running checksum and maximum. Its
permutation order follows the retained independent reference's decreasing
counter state machine, rather than copying Nim's increasing counter/unranking
implementation. All arrays remain permutations of `0..n-1`; this includes
actual traced byte-array values. Missing, duplicate, reordered or additional
events reject, even if final output is correct. The guard must remove exactly
the copies belonging to zero-first permutations, without changing any real
reversal or signed contribution.

Parallel normal witness mode retains the original scheduler. The main thread
records each successful real `createThread` return and each real `joinThread`
return; every native worker writes its exact starting/ending interval and all
events to its own file. Replay requires exactly `min(8, n!)` workers, every rank
once with no gaps/overlap, all matching ends and joins, and no extra files.
Eight additional short ranges at `n = 6` exercise odd starts, single ranks and
factorial boundaries using the exact same worker function. These are diagnostic
sequential calls, not evidence of extra production threads.

The process supervisor owns a new process group, inherits the common mutex at
a descriptor of at least 64, applies an external watchdog, reaps the leader,
and kills/reports any remaining process group before releasing the mutex.
Unexpected descendants or any cleanup intervention fail qualification. These
checks establish bounded worker lifecycle and failure cleanup; they do not
claim a full-input work witness or dynamic heap-allocation measurement.

## Commands after independent review and root clearance

From this directory, using the same Python 3.12 runtime as the current metadata
tools:

```text
python3 run_qualification.py --prepare --plan native-plan-v1.json --output attempt-v1
python3 run_qualification.py --run --plan native-plan-v1.json --reviewed-plan-sha256 <exact digest printed by prepare>
python3 -m unittest -v test_qualification.py
```

The preparation command hashes the full restored toolchain, so it also waits
for clearance. The controller is fail closed if any pin, flag, diagnostic,
complete output, work event, source delta, thread interval or cleanup differs.
The final success status deliberately retains the independent emitted-code
review gate and does not assign an application LOC or qualify a chart point.
