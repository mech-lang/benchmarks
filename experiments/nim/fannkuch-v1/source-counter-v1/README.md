# Exact normal Nim frontend and retained owner-policy capture

This separate gate measures the six exact application sources with the
unchanged, qualified retained Nim source-owner policy. It is a
**native-frontend-bound lexical/source-owner count**, not a native AST count or
a uniform logical-source metric. Application LOC remains null and approval
remains false until independent review. No canonical data is changed.

The compiler uses the actual normal-source recipes and untouched Nim 2.2.12
distribution. The existing qualified input adapter adds only these audit flags:

```text
--compileOnly:on --processing:filenames --filenames:abs --colors:off --incremental:off
```

Fresh output/cache locations preserve all original semantic, ORC, thread, SDK
and numerical flags. Real import/include events must identify exactly one
authored application file and pinned standard-library sources; unknown roots,
missing main files or unpinned library inputs reject. No scored binary is
rebuilt, and no object or output executable may appear. `compileOnly` performs
semantic compilation and can execute standard compile-time/template machinery.
It is not claimed to be a universally syntax-only operation. No application
process or native backend/link operation runs in this gate.

The exact `foreign_nim`, `foreign_core`, `foreign_future_mask` and `canonical`
bytes match the saved passing 672-fixture receipt. The older canonical module
is obtained from an exact retained dependency alias, because the current
top-level module has a different hash. The existing six-fixture frontend
adapter and Pygments 2.19.2 package identity are also retained unchanged. These
historical fixtures are reused, not rerun or relabelled. Actual imported
counter/lexer modules are recorded with hashes.

Each exact source is counted without changing a counter function or constant.
A Python profiling hook observes the unchanged `count_owned` function's local
statement decisions when it returns. The per-file ledger combines those real
statement decisions with its canonical owner events; a separately pinned Nim
lexer supplies exact significant source-token spans. Every significant source
character must have exactly one owner, every written row is retained, the
ledger total must equal the actual metric, and all diagnostics/unowned-token
lists must be empty. Both parent metrics and their complete event arrays must
equal the historical saved results. Every candidate row/unit decision must
match its proposed manual ledger. This does not approve semantic ownership by
itself; it supplies concrete evidence for independent review.

## Preserved first capture and additive wrapper repair

`capture-v1/report.json` is a failed exclusive attempt. Its first native
frontend command succeeded without warnings, and the unchanged parent counter
passed the expected 35-unit/35-row check. The new metadata wrapper then raised
`TypeError` because it supplied a second `kind` key when copying a canonical
event. No count was admitted and no application/backend process ran.

The original `capture.py`, plan and all partial bytes remain unchanged.
`capture_v2.py` changes only that wrapper to preserve the event's original
`kind` and put its wrapper classification in a separate `owner_class` field.
It also binds the failed attempt/report/raw streams. The qualified counter,
helpers, grammar, compiler flags and every application source remain unchanged.
The second capture requires a new plan and output directory under the common
mutex; it has not run at the time this protocol note was prepared.
