# Owned hash-map storage for native lowering

Compiler revision `18d4dc7cb8e7e3b6a24fdb063c19433fc041d0d8` adds an internal owned String/U64 storage backend using pinned hashbrown 0.15.5. A newly constructed table has zero capacity and grows through the library. Its entry operation accepts an arbitrary caller-supplied value; it implements no increment, window traversal, histogram or workload algorithm. Keys support empty strings, Unicode and embedded NUL bytes.

This backend is **not yet selected by compiled Mech programs**. The source-written counting procedure still uses its existing canonical map path. No source hash representation contract, native owner-region lowering, entry batching or new benchmark result is qualified by this study.

The owner retains table/key allocations on the same finite memory account and library work ledger. New keys and replacement tables are admitted together before allocation or content mutation. The old table stays funded throughout growth. Hashing and collision-chain work are prepaid from capacity and stored key bytes, without assuming favourable hash distribution. Keys and tables retire before their reservations. The limits here apply to this storage owner; native integration must additionally prove current call/frame coexistence, source aliasing, selected implementation identity and publication authority.

Nine storage checks cover arbitrary values and replacement by smaller values, Unicode/NUL/empty keys, complete hash collisions, long shared prefixes, repeated growth, release of all retained claims, entry limits, retained/temporary byte boundaries, global memory denial and retry, overflow, and compute/comparison denials before hashing. A recording collision hasher verifies that library hashing occurs and that denied/retried lookups do not reach hashing or replenish their work account. The exact/one-short replacement-peak case preserves capacity, contents and accounting on denial. The broad native suite passes 179 checks, including these nine; three pre-existing checks remain ignored.

`storage-v1` and `storage-v2` retain intermediate passing checks. `native-regressions-v1` is the final broad suite. All process subjects run serially under the shared benchmark mutex, use finite budgets and retain owned-process cleanup receipts. No quantitative timing samples or canonical dataset changes occur.

The next lowering stage must establish an owner across the actual Mech state carrier, reject or preserve aliases to previous map versions, keep the value computation in compiled Mech, and materialize canonical values at observable boundaries. Any explicit source hash contract must survive bytecode round trips. Ordinary abstract-map dense/query optimizations remain available; no hidden benchmark switch or source-name match should choose this representation. Full-input work witnesses and performance measurements follow those checks.
