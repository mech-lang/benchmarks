# Streamed record compaction

A generic Mech runtime change removes the second memory pass used to join record
body lines. For a single-byte record prefix with an empty join separator, body
spans are appended directly from buffered input, excluding LF and one trailing
CR per physical line. Other prefixes and separators retain the existing path.
The application, emitted Cranelift object and record semantics are unchanged.

[Results](RESULTS.md) contain the matched comparison. The candidate uses 10.7%
less elapsed time with four partitions; Rust remains faster in this workload.
These measurements are experimental and have not replaced website endpoints.

## Implementation and qualification

- Base compiler/runtime: `6de19875e2266f39c93712800c400672a44b98c9`.
- Changed runtime: `6634f1f4d59c0a2eebee44065f236f8647703464`, branch
  `codex/record-streaming-compaction` in `mech-lang/mech`.
- Unchanged application: [revcomp.mec](../../../archive/workloads/revcomp/revcomp.mec),
  seven physical source rows. No new normalized or canonical formatted LOC claim.
- [compiler.json](compiler.json) pins sources, emitted objects, toolchain,
  dependencies and test results. Before/after sources and patch are retained in
  `compiler-snapshot/`; binaries and generated build projects are omitted.
- Eight relevant runtime tests pass. The parser test compares 2,736 combinations
  of input, prefix, separator and small buffer capacity against an independent
  line-contract reference. It covers CRLF splits, literal CR, partial headers,
  inline markers, empty records, non-ASCII bytes and EOF. Another test covers
  interrupted reads and real I/O errors. Complete logs are in `tests/`.
- All 61 parent/candidate bounded behaviors agree, including exit status and
  complete output/error bytes. Eleven existing source-contract differences from
  the broader shared FASTA oracle remain explicitly listed in
  [qualification-v1/results.json](qualification-v1/results.json). In particular,
  the generic record interface does not silently discard FASTA comments,
  preheader data or all lone CRs. This is not a claim of full FASTA conformance.
- All five execution variants pass the official N=1000 output check and every
  complete timed output matches the full generated-workload reference.

The official [reverse-complement specification](https://benchmarksgame-team.pages.debian.net/benchmarksgame/description/revcomp.html)
requires growing buffered input rather than sizing a single allocation from a
file. Neither Mech version obtains the input file size or precomputes results.
The protected [Rust #1](https://benchmarksgame-team.pages.debian.net/benchmarksgame/program/revcomp-rust-1.html)
application is retained byte-for-byte, including original attribution; only its
build package pins current dependencies. Its source is not optimized or edited.

## Reproduction and receipts

`build_baseline.py` builds the parent before the runtime change;
`build_candidates.py` builds the changed runtime and unchanged Rust submission.
The same frozen Mech CLI emits identical application objects in both builds;
the generated applications link the runtime from the checkout at build time.
Exact build commands/environments are in the two build receipts. Rust uses
`-C target-cpu=native`, memchr 2.8.3 and rayon 1.12.0. Cargo manifests and locks
are retained. Reproduction on another checkout requires adapting absolute paths
in the scripts and creating both base/candidate runtime builds in that order.

`qualify.py` runs the retained bounded corpus. `run.py` conducts seven shuffled
serial rounds under the shared benchmark mutex; it includes full process startup,
input, computation, all output, flush and shutdown, excluding AOT compilation.
Mech uses its existing trusted legacy I/O path; secured capability activation is
not newly timed. Mech runs with four or eight partitions, Rust with eight Rayon
workers. No concurrent benchmark or compiler is launched.

Input is 254,166,745 bytes, generated by FASTA N=25,000,000. Exact input and output
hashes, environments, binary hashes, all 35 samples, process birth/closure receipts
and power/memory snapshots are in `run-v2/`. Full outputs are actually written,
then checked after process closure, then removed with a size/hash receipt.
Bounded outputs remain complete. The initial Rust launch failed because a file
copy lost execute permission; it exited 126 before any timing samples. The
metadata-only correction and closed failed attempt remain in `run-v1/`,
`attempts-v1/` and `preflight-review.json`.

`python3 experiments/mech/revcomp-streaming-v1/verify.py` replays retained proof
checks without launching benchmarks. `seal.json` hashes every retained study
artifact. Verification of omitted full outputs checks the recorded complete-output
hash receipts; it cannot reconstruct deleted bytes without rerunning the subject.
