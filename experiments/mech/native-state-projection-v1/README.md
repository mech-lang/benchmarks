# Native canonical state bindings

This study extends native structural pattern binding from U64 fields to supported canonical child values. The Mech counting procedure keeps its window traversal, guarded lookup, increment, insertion and state transitions in source. The added runtime operation only projects and materializes a selected child value; it implements no counting algorithm.

A native borrowed-measurement meter is tied to the identity of its live invocation account. It admits recursive measurement on that same cumulative ledger without manufacturing a resident turn plan or a kernel execution permit. Canonical construction separately admits output size, clone size, retained nodes, simultaneous ownership, draft/finalization storage and the complete schema arena before constructing a draft. Publication through the typed arena follows successful construction and ownership import. Packed collections, field-label drafts and foreign Dynamic roots remain excluded from this new projection route pending appropriate expansion witnesses.

Native IR28 and work policy41 identify the new projection semantics and accounting; ABI15's frame layout is unchanged. The stale-object check includes the preceding IR27 and policy40. Build-owned descriptor images reconstruct the new observation only through their normal confined loader and retain schema/path validation.

`execution-v4` executes one compiled counting procedure with a runtime width argument, checking every key/count for seven widths and three sequences, on original and bytecode-decoded artifacts (42 cases). This is native machine-code execution through the JIT owner, not a standalone executable qualification. The later native regression suite also checks build-owned descriptor round trips and emitted object identities. No new benchmark timings are collected.

Earlier attempts are retained. `execution-v1` and `execution-v2` record test API errors. `execution-v3` records a real finite work denial at the unchanged one-billion-unit invocation limit: a test program duplicated seven source call sites and its repeated schema/ownership work exceeded that limit. The final fixture compiles the counting procedure once and supplies the seven widths as runtime inputs in separate fresh correctness invocations; it does not raise that cap. This result is not a complete-input resource qualification.

`map-contracts-v1` records corrected test construction errors. `map-contracts-v2` passes the entry/projection and source contract checks, including foreign-account rejection, denied output admission, unchanged source ownership and retry. Final validation passes 418 distinct checks: 198 engine checks, one catalog check, 169 native host checks and 50 map/source integration checks; four pre-existing checks remain ignored. The engine checks include a failed canonicalization preflight whose spent comparison prefix remains charged across retries.

A physical hash-table representation/entry contract, ownership-aware hash lowering, standalone source/decoded executable qualification and full-input work validation remain pending. The canonical benchmark dataset is unchanged. All build/test subjects run serially under the existing shared mutex and produce non-quantitative owned-process receipts.
