# Retained JDK capture capability

This source and metadata audit invoked no JVM, compiler, disassembler, or benchmark and did not hash runtime files. Runtime pins in the companion JSON are copied from the already retained compiled-work plan.

The retained AArch64 HotSpot library contains all proposed diagnostic flag names and CompileCommand quiet/print help, XML print_nmethod and MachCode boundaries, C1/C2 compiled-method headings, machine-code ranges, and ImmutableOopMap text. No hsdis file was found under the retained Java home. The library itself describes abstract disassembly when hsdis is unavailable. This supports attempting raw machine-byte and OopMap capture with LogCompilation/LogVMOutput and DisplayVMOutput disabled.

These strings do not prove that a particular method compiles or that every diagnostic, including the initial missing-hsdis warning, is routed into the XML file. The authorized capture must independently require exact benchmark stdout, empty stderr, targeted compiled-method identity, actual machine bytes, and relevant OopMap evidence. Missing capture is a failed evidence gate. This audit makes no work-qualification or timing claim.
