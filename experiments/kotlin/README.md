# Kotlin qualification

The retained cohort contains twenty source forms across ten workloads. Each form
counts its Kotlin main and helper input. Three independent compilations and two
complete `javap -p -c -s -v` owner captures succeeded before archive relocation
interrupted prerequisite verification. Their receipts and generated classes are
reused without recompilation. The closed generic JVM probe is also reused.

`tools/qualification/kotlin_resume.py` verifies the retained dependency closure,
source bindings, command receipts, and exact generated class sets. It resolves
archived repository paths through the migration map while preserving original
host toolchain and class paths. The three explicitly listed retired orchestration
documents retain their editorial replacements and are never executed.

The default command creates a pinned plan without native execution. Both modes
require fresh output and build directories and exclusive ownership of the shared
timing mutex. `--execute` adds only seventeen compilations and eighteen owner
captures. Successful commands are never retried automatically. Diagnostics,
timeouts, changed pins, unexpected artifacts, or incomplete receipts stop the run
and preserve partial evidence.

```sh
python3 -B tools/qualification/kotlin_resume.py \
  --output /absolute/path/to/new-evidence \
  --build /absolute/path/to/new-build
```

Class capture alone does not qualify benchmark results. The following gates
remain required before timing or chart admission:

- Review every generated owner and instruction against its counted source bundle.
- Close actual subject runtime dependencies and verify the measured JIT path.
- Verify raw standard input/output and bounded workload results.
- Verify required allocation, lifetime, map-window, and arithmetic work.
- Qualify complete canonical and formatted source counts.
- Run the full prescribed workloads with sequential fresh-process samples and
  matched unchanged Mech controls, then reconcile results independently.

The lightweight fixtures in `test_resume.py` exercise receipt failures, path
relocation, changed source rejection, class-set completeness, and additive scope
without invoking a compiler, JVM, or benchmark.
