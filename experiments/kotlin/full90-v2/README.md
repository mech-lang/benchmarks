# Kotlin full90 with additive single-entry evidence

[kotlin_full_v2.py](../../../tools/qualification/kotlin_full_v2.py) admits the [twenty-form required-work receipt](../required-work-qualification-v2/qualified-work.json) and the existing qualified canonical source counts. It preserves the two failed single-entry producers and requires the successful final optimized-pi continuation plus all independent instruction reviews. Pi requires `single_entry_execution_path`: an interpreted main is valid only when the complete actual compiler log and retained bytecode prove that path.

The adapter privately loads the exact frozen [full90 implementation](../../../tools/qualification/kotlin_full.py), SHA-256 `06f52fac0287b64ae0c231df8f8eb4a4793112a91efb01c5dde9b107c743c6e7`. Only prerequisite validation and the new controller/packet identity are replaced. Its sampler, schedule, output validation, process supervision and failure accounting are unchanged: twenty Kotlin forms and ten matched Mech controls, three samples each, 90 serial slots, canonical full inputs, direct JVM main with 8 GiB G1 and eight active processors. Startup, class loading, JIT, complete input/output and shutdown remain timed.

No runnable plan is included. The sequence after independent source/receipt review is:

1. `draft --qualified-work <absolute-qualified-work.json> --qualified-work-sha256 <reviewed-sha256> --plan <fresh-draft.json> --output <fresh-run-directory>` reads evidence and emits a metadata-only draft.
2. `prepare --draft <absolute-draft.json> --draft-sha256 <reviewed-sha256> --plan <fresh-plan.json>` acquires the common timing mutex, verifies the full pin/artifact/input closure and emits the executable plan.
3. `run --plan <absolute-plan.json> --plan-sha256 <reviewed-sha256>` runs once through the continuous inherited mutex and suite lease. Use the retained Python with `-I -S -B -u` and the separately reviewed durable launcher.

All paths must be absolute physical paths. A failed or interrupted sample is retained and receives the unchanged isolated-failure accounting; there is no automatic retry, overwrite or resume. Full-size heap feasibility is not a prerequisite claim. A full-size failure cannot create a qualified timing. Canonical counts remain true, formatted counts remain false/null, and timings/chart admission remain false until the independent completed-run reconciliation.
