# Prolog spectral-norm source proposal

This packet contains **unexecuted source candidates**. It changes no canonical program, runtime, result, or source count. The parent is an exact copy of the retained compact Prolog spectral-norm implementation. Neither candidate has been parsed or compiled by Prolog, checked for numerical output, timed, or admitted. Its source-ownership numbers are manual proposals awaiting independent review and the retained native-reader qualification.

The serial candidate removes the orientation test from the inner column loop by using separate forward and transpose row predicates. It also writes `NextAccumulator is Accumulator + (A * Value)` in place of the separate multiplication temporary and addition. The syntax retains the multiplication as the right operand of the addition; whether SWI's optimized arithmetic emits exactly equivalent operations still needs native numerical evidence. The denominator formula, coefficient predicate, ascending column order, power iterations, final dots, formatting and CLI support are unchanged.

The eight-worker candidate uses those same specialized row predicates and constructs exactly eight contiguous row-block goals per product. The boundaries of block `b` are `floor(b*N/8)` and `floor((b+1)*N/8)`. Each block returns its own ascending list of row results. Ordinary `concurrent(8, Goals, [])` returns those bindings; `append/2` restores block order, and the resulting list builds a fresh output vector. This spends eight input copies per product, rather than one input copy per row. There is no shared mutable output, `nb_setarg`, foreign helper, matrix cache, or change to the mathematical workload. Empty blocks are intentional for small N. The main predicate preserves the parent's N=0 branch before any multiply.

All four required predicates remain written: `coefficient/3`, `apply/3`, `apply_transpose/3`, and `apply_ata/3`. The ten `power/6` iterations still perform two `apply_ata/3` applications each: twenty AtA applications and forty full N-by-N products. At N=5500, this is 1,210,000,000 coefficient evaluations, multiplications and accumulator additions. Parallelism changes row scheduling, not column reduction order. No speed claim follows from this source review; copying, worker startup, results and vector construction can outweigh the reduced dispatch cost.

No runtime was restored.

The pinned documentation at lines 125–140 requires independent goals and says worker goal copies return their variable bindings. The implementation at lines 167–192 creates the bounded worker pool and waits for all jobs. Lines 203–208 collect each goal's free variables and enqueue the module-qualified goal. Lines 219–239 use its job ID to unify returned bindings with the correct caller slot; completion order therefore does not reorder the `Chunks` list. Lines 263–272 execute a job and return only its variable list. Successful cleanup at lines 282–300 joins workers and destroys queues. With a ground input vector and only one fresh output-list variable per goal, results require no shared variable or global mutation. The [current API page](https://www.swi-prolog.org/pldoc/man?predicate=concurrent/3) is supplementary; the pinned 10.0.2 source is the authority for this proposal.

## Required qualification before timing or admission

The [source-only plan](plan.json) records the exact seven shared bounded cases and the full output reference. Add N=0 and row-block boundaries N=7,8,15,16,17. Differential checks must compare forward, transpose and AtA output vectors on asymmetric, nonconstant and signed inputs, as well as final rounded text. Exact component comparison is stronger than accepting a nine-digit norm alone. Compare serial and block candidates against the unchanged parent within the same pinned runtime; a source-level arithmetic expression is not native proof of rounding identity.

Inspect actual generated goal lists: exactly eight, contiguous nonoverlapping ranges whose row counts sum to N, ground input vectors, distinct result variables and output order matching row order. Verify exceptions/failures propagate and every worker is joined. The standard library source establishes its intended contract; future bounded execution must establish that the candidate uses that contract correctly. Keep any instrumentation in a separate untimed source twin, and pin it to these exact sources.

Use the retained SWI 10.0.2 executable and complete runtime-file pins, original `-q -O -f none --stack-limit=8g` flags and the retained explicit-goal/success-halt invocation. Runtime restoration, candidate compilation/load validation, bounded runs, full matched runs, power/competition controls and source counting all remain pending. Root owns the common serial benchmark lock and the execution window. No new runtime settings or unmeasured replacement of old samples is proposed.
