# Publication from two preserved measurement cohorts

The additive publication tools consume independently verified, closed evidence.
They do not run SWI-Prolog, a compiler or a benchmark, and their preparation does
not establish that the timing cohort has completed. The original cancelled
study, continuation producer receipts and their admission flags remain unchanged.

[`prolog_linear_export.py`](../../../tools/qualification/prolog_linear_export.py)
reproduces the [runtime metadata review](runtime-metadata.md) under the same four
owner, study and common leases, then constructs a private candidate. It retains
the eighteen unchanged Prolog forms and the two explicit aliases of the linear
reverse-complement implementation. Every authored compiler input and helper
contributes its qualified canonical count. Formatted LOC remains unavailable.

Each sample carries its actual producer plan, report, terminal, raw receipt,
sampler receipt and outer supervisor reference. The six Prolog regex samples and
three corresponding Mech samples retain their original full90 evidence; the
remaining workloads use the continuation evidence. Local attempt numbers are
paired with their cohort identity. No combined90 producer receipt is invented,
and original attempt 10 supplies no timing or timeout result.

Failed workload records remain in the twenty-profile inventory. Their median,
standard deviation and matched-control ratio remain null. An incomplete failed
process may have no complete-output byte count, hash or validation object; those
fields remain null, without an invented output claim. Successful records still
require all complete-output fields. An endpoint is eligible only when its source
form and matched Mech control each have three qualified full-workload samples.

[`import_prolog_linear.py`](../../../tools/qualification/import_prolog_linear.py)
independently reproduces that candidate before constructing three publication
files: `data/benchmarks.json`, `data/languages.json` and `site/src/languages.mjs`.
Its default writes a new private directory containing those files and exact
original backups. Existing programs, source content, benchmark baselines,
language entries and aggregate prefixes remain unchanged. A new minimum below
an existing baseline is rejected for separate review. No formatted endpoints or
formatted aggregate are added.

All twenty forms enter the program inventory; only qualified fastest/smallest
endpoints enter the selected chart programs. Per-program publication records
retain `timing_sd`, including null on failed forms. The language metadata reports
SWI's interpreted QLF virtual-machine execution, dynamic typing, logic style and
garbage collection. The separately reviewed site trait source containing the
Logic option is a pinned importer prerequisite. The importer adds a Logic
language group if absent.

The output directory must be new and outside the repository. An explicit
`--apply` also replaces the three public inputs while all four leases remain
held. Replacement registration is protected from handled termination signals.
Any body failure restores replaced files; any final evidence-closure failure
invokes restoration before releasing the leases. Restoration accepts only the
known original or prepared bytes, so it cannot overwrite an unrelated third
version. A success receipt is emitted only after the final closure checks pass.
Every journaled target is checked against its exact prepared bytes during
replacement and again after the final evidence recheck, before leases release.
Temporary-file cleanup only removes a file created by that replacement call.
Catalog export, repository validation and site tests remain separate required
publication checks.

The [release record](release-metadata-v1.json) identifies the language's 1972
origin, derived explicitly from SWI-Prolog's [2022 fiftieth-anniversary
announcement](https://www.swi-prolog.org/news/53a33da0-cfa9-11ec-99f9-00163e8f424e).
The general [QLF](https://www.swi-prolog.org/pldoc/man?section=qlf) and
[garbage-collection](https://www.swi-prolog.org/pldoc/man?section=gc) documentation
supports classification; exact runtime version, flags and observed defaults
come from the separately retained native metadata, not the current website's
runtime version.

The ten exporter and eighteen importer pure tests use saved source/metadata and
an explicitly synthetic future ledger. They cover source aliases and ownership,
both sample cohorts, missing failed-output fields, failure/control exclusion,
canonical-only endpoints, fixed baselines, unchanged prior data, Logic-group
membership and exact-byte rollback in temporary directories. They neither read
the live continuation report nor run file-mode verification or native commands.
